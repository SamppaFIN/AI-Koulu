Suorituskyky on käytettävyyttä: hidas lataus tai viivästynyt reaktio painallukseen tuntuu käyttäjälle samalta kuin rikkinäinen toiminto (luku 3). Googlen Core Web Vitals -mittarit mittaavat kolmea asiaa: latautumista, vasteaikaa ja visuaalista vakautta.

## 5.1 Kolme mittaria

| Mittari | Mitä mittaa | Hyvä | Huono |
|---|---|---|---|
| <TermTooltip term="lcp">LCP</TermTooltip> (Largest Contentful Paint) | Aika navigoinnin alusta siihen, kun näkymän suurin kuva, tekstilohko tai video on piirretty | ≤ 2,5 s | > 4 s |
| <TermTooltip term="inp">INP</TermTooltip> (Interaction to Next Paint) | Vuorovaikutuksen alusta seuraavan ruudun piirtämiseen; raportoidaan käynnin pisimpiä viiveitä | ≤ 200 ms | > 500 ms |
| <TermTooltip term="cls">CLS</TermTooltip> (Cumulative Layout Shift) | Suurin odottamattomien asettelusiirtymien ryöppy | ≤ 0,1 | > 0,25 |

Raja-arvot ovat web.devistä <Reference id="google2024" /> <Reference id="webdev-lcp" /> <Reference id="webdev-inp" /> <Reference id="webdev-cls" />. Sivu läpäisee mittarin, kun **75. persentiili** sivulatauksista on hyvällä alueella, erikseen mobiilissa ja desktopissa <Reference id="google2024" />. Persentiili valitaan siksi, että keskiarvo piilottaisi hitaiden laitteiden ja yhteyksien käyttäjät.

**INP** korvasi aiemman FID-mittarin (First Input Delay) Core Web Vitalsina maaliskuussa 2024 <Reference id="webdev-inp-launch" />. FID mittasi vain ensimmäisen vuorovaikutuksen viiveen ennen käsittelyn alkua. INP mittaa kaikki napsautukset, napautukset ja näppäinpainallukset koko käynnin ajalta, ja viive lasketaan siihen asti, kun selain pystyy piirtämään seuraavan ruudun. Vieritys, hiiren vienti elementin päälle ja zoomaus eivät ole mukana <Reference id="webdev-inp" />.

**CLS:n** yksittäisen siirtymän pistemäärä on vaikutusosuus kertaa siirtymäosuus: kuinka suuren osan näkymästä siirtyvät elementit kattavat ja kuinka pitkän matkan ne liikkuvat näkymän kokoon suhteutettuna. Siirtymät ryhmitellään ikkunoihin, joissa siirtymien väli on alle sekunti ja koko ikkuna enintään viisi sekuntia. CLS on suurimman ikkunan summa. Siirtymät, jotka tapahtuvat 500 ms sisällä käyttäjän toiminnosta, eivät ole odottamattomia, eikä niitä lasketa <Reference id="webdev-cls" />.

<div class="formula">siirtymän pistemäärä = vaikutusosuus · siirtymäosuus</div>

## 5.2 Kenttä- ja laboratoriomittaus

- **Kenttädata** (real user monitoring) mitataan oikeiden käyttäjien selaimissa. Se kertoo todellisen kokemuksen, ja Core Web Vitals -arvio perustuu siihen.
- **Laboratoriodata** (esimerkiksi Lighthouse) mitataan yhdellä koneella vakioiduissa oloissa. Se on toistettavaa ja sopii vianetsintään, mutta ei kerro, millä laitteilla ja yhteyksillä käyttäjät oikeasti ovat. INP:tä ei voi mitata ilman vuorovaikutusta, joten laboratoriossa seurataan sen sijaan, kuinka kauan pääsäie on latauksen aikana varattuna (Lighthousessa Total Blocking Time).

Kehittäjän kone ja verkko ovat yleensä nopeampia kuin käyttäjien. Testaa siksi myös hidastetulla suorittimella ja verkolla.

## 5.3 LCP:n parantaminen

LCP-elementti on usein pääkuva tai suurin otsikko. Viive syntyy neljästä osasta: palvelimen vastaus, resurssin löytäminen, sen lataus ja piirto.

```html
<img src="kuva-1200.avif"
     srcset="kuva-800.avif 800w, kuva-1200.avif 1200w"
     sizes="(max-width: 800px) 100vw, 50vw"
     width="1200" height="675"
     fetchpriority="high" alt="…">
```

- Älä aseta LCP-kuvalle `loading="lazy"`: laiska lataus viivästää juuri sitä kuvaa, jota LCP mittaa.
- `fetchpriority="high"` nostaa kuvan latausjärjestyksessä.
- `srcset` ja `sizes` antavat selaimen valita näyttöön sopivan koon, jolloin mobiililaite ei lataa desktop-kokoista kuvaa.
- Jos LCP-elementti on tekstiä, fontin lataus voi viivästää sitä. `font-display: swap` näyttää tekstin heti varafontilla.

## 5.4 INP:n parantaminen

Selain käsittelee vuorovaikutuksen pääsäikeessä. Jos pääsäikeessä on käynnissä **pitkä tehtävä** eli yli 50 ms kestävä tehtävä, vuorovaikutus odottaa sen loppuun <Reference id="webdev-long-tasks" />. Ratkaisu on pilkkoa työ osiin ja antaa selaimelle välissä vuoro:

```js
async function kasitteleKaikki(rivit) {
  for (const rivi of rivit) {
    kasittele(rivi);
    // Anna selaimelle vuoro käsitellä vuorovaikutukset ja piirtää
    if (globalThis.scheduler?.yield) await scheduler.yield();
    else await new Promise((r) => setTimeout(r, 0));
  }
}
```

`scheduler.yield()` jatkaa funktiota ennen muita jonossa olevia tehtäviä. `setTimeout` toimii kaikissa selaimissa, mutta jatko menee jonon loppuun. Tilanteessa 11/2026 `scheduler.yield()` toimii Chromessa, Edgessä ja Firefoxissa, mutta ei Safarissa <Reference id="webdev-long-tasks" />.

Muita keinoja: lataa vähemmän JavaScriptiä, siirrä raskas laskenta Web Workeriin, näytä palaute (esimerkiksi painikkeen tila) ennen raskasta työtä ja vältä suuria DOM-päivityksiä yhdellä kertaa.

## 5.5 CLS:n parantaminen

| Syy | Korjaus |
|---|---|
| Kuva tai video ilman mittoja | `width`- ja `height`-attribuutit tai CSS:n `aspect-ratio`, jolloin tila varataan ennen latausta |
| Mainos, upotus tai myöhemmin ladattava komponentti | Varaa tila etukäteen kiinteällä vähimmäiskorkeudella |
| Fontin vaihto muuttaa tekstin kokoa | Varafontti, jonka mitat on sovitettu (`size-adjust`), tai `font-display: optional` |
| Sisältö lisätään olemassa olevan yläpuolelle | Lisää sisältö alle tai käyttäjän toiminnon seurauksena |

## 5.6 Koettu suorituskyky

Kun odotusta ei voi poistaa, sen voi tehdä ymmärrettäväksi:

- **Runkonäkymä** (skeleton) näyttää tulevan sisällön rakenteen ennen dataa. Se kertoo, mitä on tulossa, ja estää asettelun hyppäämisen, kun runko on samankokoinen kuin lopullinen sisältö.
- **Optimistinen päivitys** näyttää toiminnon tuloksen heti ja peruu sen, jos palvelin hylkää muutoksen. Sopii toimintoihin, jotka onnistuvat lähes aina ja jotka on helppo perua, kuten tykkäykseen. Maksuun se ei sovi.
- **Suoratoisto** näyttää pitkän vastauksen sitä mukaa kuin se syntyy, mikä on kielimallisovelluksissa tavallista (luku 7).

Runkonäkymän animaatio on koriste, joten se poistetaan, kun `prefers-reduced-motion` on päällä (luku 2), ja se piilotetaan ruudunlukijalta `aria-hidden`-attribuutilla. Lataustila kerrotaan ruudunlukijalle tekstinä, esimerkiksi `aria-busy`-attribuutilla tai tilaviestillä.

## Sudenkuopat

- **Optimointi omalla koneella.** Mittaa kenttädatasta tai hidastetulla laitteella.
- **Laiska lataus kaikille kuville.** Näkymän yläosan kuva latautuu silloin myöhään.
- **Yksi suuri JavaScript-paketti.** Lataa vain se, mitä sivu tarvitsee. Tämä sivusto renderöi sivut valmiiksi HTML:ksi ja lataa React-koodin vain demoille (luku 6).
- **Keskiarvon seuraaminen.** Core Web Vitals arvioidaan 75. persentiilistä.
